# Қазақ тілінде ASR қайда сынады

Қазақ тіліндегі сөйлеуді тану сапасының аудиті. Мақсат "WER қандай" деген сұраққа
жауап беру емес, **осы WER неден тұрады** және агглютинативті, өз графикасы бар
тілде оған қаншалықты сенуге болатынын түсіну.

## Іске қосу

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
pip install --index-url https://download.pytorch.org/whl/cpu torch torchcodec

python src/prepare_data.py --minutes 12
python src/transcribe.py --model large-v3 --lang kk --device auto
python src/transcribe.py --model small    --lang kk --device auto
python src/transcribe.py --model large-v3 --lang none --device auto   # тіл нұсқауынсыз
python src/evaluate.py --hyp results/hyp_large-v3_kk.tsv

# "студия vs краудсорсинг" салыстыруы, бірдей модельмен
python src/prepare_data.py --source common_voice --out data_cv --minutes 4
python src/transcribe.py --model large-v3 --lang kk --device auto --data data_cv --results results_cv
python src/evaluate.py --hyp results_cv/hyp_large-v3_kk.tsv --data data_cv --results results_cv
```

Жоба әдепкі бойынша локальді кэшті (`.hf_cache`) қолданады, `~/.cache/huggingface`-ге
тәуелді болмау үшін және VS Code сияқты sandbox орталарда бұзылмау үшін. macOS пен
CPU-да `--device cpu` және `--compute_type int8` жақсы жұмыс істейді, GPU-да
`--device cuda --compute_type int8_float16`.

**macOS: FFmpeg 4-8 нұсқасы керек, соңғысы емес.** `datasets` кітапханасы аудионы
`torchcodec` арқылы декодтайды, ал ол нақты FFmpeg нұсқаларына линктелген.
`brew install ffmpeg` 2026 жылы FFmpeg 9 орнатады, онымен `torchcodec` құлайды
(`Library not loaded: @rpath/libavutil.XX.dylib`). Жұмыс істейтін нұсқа:
```bash
brew install ffmpeg@7
export DYLD_FALLBACK_LIBRARY_PATH="$(brew --prefix ffmpeg@7)/lib"
```
(бұл экспортты `~/.zshrc`-ке қосып қойған дұрыс, әр жолы қайталамау үшін). Colab-та
бұл мәселе кездеспеді, ондағы жүйелік FFmpeg дұрыс нұсқада тұр.

Colab-та (T4, тегін тариф) 12 минут аудионы `large-v3` моделімен, `int8_float16`
режимінде өңдеу шамамен 5-8 минут алады.

## Тесттер

Unit test-тер желі мен аудиосыз таза функцияларды тексереді: нормализация мен
стемминг (`kk_text.py`), сонымен қатар қате классификаторы мен bootstrap есебі


## Не есептейміз және неге

| Метрика | Не істейді | Айырма нені көрсетеді |
|---|---|---|
| `WER_raw` | нормализациясыз | бастапқы нүкте |
| `WER_norm` | регистр, тыныс белгілері, дефис алынып тасталады | `raw − norm` = модельдің емес, **метриканың** қатесі |
| `WER_fold` | + ә/ө/ұ/ү/і/ң/қ/ғ орыс аналогтарына ауыстырылады | `norm − fold` = **қазақ графикасының** бағасы |
| `WER_stem` | + жалғаулар кесіледі | `norm − stem` = **морфологияның** бағасы |
| `CER_norm` | символ деңгейінде | агглютинативті тілде WER-ден тұрақтырақ |

Жұмыстың негізгі тезисі: қазақ тілінде бір қате жалғау бүкіл сөзді толық қате
етіп көрсетеді, сондықтан WER ағылшын тіліне қарағанда деградацияны жүйелі түрде
үлкейтіп көрсетеді. `WER_stem` пен `CER` модель шын мәнінде қанша мағынаны
сақтап қалғанын көрсетеді.

`evaluate.py` сонымен қатар `WER_norm` мен `WER_stem` үшін 95%-дық сенімділік
аралығын (confidence interval) есептейді, уттеранс бойынша bootstrap әдісімен
(1000 қайта сынама алу). Ондаған жазбадан тұратын үлгіде бұл аралық кең болады,
онсыз бір WER саны шындықтан гөрі сенімдірек көрінеді.

## Қате типологиясы

`src/evaluate.py::classify` классификаторы әр ауыстыруды келесідей бөледі: арнайы
әріптер (ә/ө/ұ/ү/і/ң/қ/ғ а/о/у/и/н/к/г болып құлаған жағдай), тек жалғау
(түбір сәйкес келгенде, жалғау сәйкес келмегенде), арнайы әріптер плюс жалғау
бір мезгілде, фонетикалық жақын форма, орыс графикасына кету, сөздің толық
ауыстырылуы, және сөздің түсіп қалуы немесе артық қосылуы.

Бөлек: символ ауыстыру матрицасы, галлюцинация кандидаттары (гипотеза эталоннан
шамадан тыс ұзын болған жағдай) және автоматты анықталған тіл үлесі.

## 1. Деректер

Екі дереккөз, екеуі де формальді түрде "оқылған" сөйлеу. Спонтанды қазақ тіліндегі
сөйлеудің адал, streaming арқылы қолжетімді корпусы табылмады (қараңыз
`src/prepare_data.py`: issai/Kazakh_Speech_Corpus_2 рухы бойынша ең жақыны,
бірақ 80+ ГБ бір өңделмеген tar.gz түрінде, уттерансқа бөлінбеген, мұндай
көлемдегі audit үшін жарамайды).

| | FLEURS | Common Voice |
|---|---|---|
| Дереккөз | google/fleurs, kk_kz, test | Common Voice kk, test |
| Сөйлеу түрі | студиялық дикторлық оқу | краудсорсинг: дауыстап, дайын мәтінді оқиды |
| Жазу жағдайы | бақыланатын, бір диктор бір клипте | әртүрлі микрофон/құрылғы/акцент, шу |
| Көлемі | 43 уттеранс, 12.05 мин | 46 уттеранс, 4.10 мин |
| Модель | `large-v3`, lang=kk, GPU (Colab T4) | `large-v3`, lang=kk, GPU (Colab T4) |

Екі жағында да модель бірдей (`large-v3`), бұл тікелей парлы салыстыру: төмендегі
сандық айырма нақты жазу жағдайының бағасы, әлсіз модель әсері емес.

## 2. Қате кестесі

Парлы `large-v3`/`large-v3` прогоны үшін толық кестелер (`results/table_large-v3_kk.tsv`,
`results_cv/table_large-v3_kk.tsv`) осы папкаларда Colab-тан көшірілгеннен кейін
пайда болады (notebook-тегі 6-ұяшық осыны істейді, егер прогон мен сақтау бір
сессияда өтсе). Қазір репозиторийде осы прогонның агрегатталған статистикасы
ғана бар (`results*/metrics_large-v3_kk.json`), ал уттеранс бойынша толық кесте
ескі, локальді, `small` моделімен жасалған прогоннан (`results_cv/table_small_kk.tsv`),
нақты мысалдар сол жерден:

| reference | hypothesis | уттеранс WER |
|---|---|---|
| қайтқан малға қасқыр өш | қайтыған мауға ғазкүроші | 1.0 |
| адал ұл оздырады жаман ұл тоздырады | әдал өл өздірады жаман өл төздірады | 0.83 |
| ағайынның беті қисық болса да бауыры қисық болмайды | ағайынын беті қисқ болса да бауры қисқ болмайда | 0.63 |

Екінші мысалда сипатты паттерн көрінеді: "оздырады"→"өздірады", модель сөзді
дерлік толық дұрыс естіді, бірақ жүйелі түрде ә/ө/ұ/ү дұрыс емес жерге қояды.
Бұл кездейсоқ шу емес, қазақ фонетикасындағы жүйелі әлсіздік.

## 3. Тип бойынша талдау

| Тип | FLEURS (n=43) | Common Voice (n=46) |
|---|---|---|
| жақын форма (фонетика/қате басу) | 59.8% | 60.0% |
| сөздің толық ауыстырылуы | 13.2% | 15.5% |
| сөз қосылуы | 7.7% | 1.3% |
| сөз түсіп қалуы | 6.4% | 6.5% |
| жалғау (морфология) | 5.1% | 5.8% |
| арнайы әріптер (ә/ө/ұ/ү/і/ң/қ/ғ) | 4.3% | 6.5% |
| орыс графикасына кету | 2.6% | 1.3% |
| арнайы әріптер + жалғау | 0.4% | 3.2% |

Модель бірдей болғандықтан, дәл осы нәтиже қызық: "жақын форма" үлесі дерлік
өзгермеген (59.8% мен 60.0%), "сөз түсіп қалуы" да солай (6.4% мен 6.5%). Яғни
шулы жазу жағдайы модель қатесінің сипатын өзгертпейді, тек оның жалпы деңгейін
көтереді (4-бөлімді қараңыз, WER шамамен 2 есе өсті). "Арнайы әріптер + жалғау"
категориясы айтарлықтай өсті (0.4% → 3.2%): шулы жазбада модель бір сөзде графика
мен жалғауды бірден шатастырады жиірек, яғни бір реттен көбірек сигнал жоғалтады.

Символ ауыстырулары да сипаты бойынша ерекшеленеді. FLEURS-та модель көбіне
әріпті мүлдем жоғалтады (`∅→ы`, `ы→∅`, `о→∅`) немесе қазақ әрпін орыс аналогына
ауыстырады (`х→қ`, `ң→н`). Common Voice-та үшінші паттерн қосылады: қазақ
әріптерінің өзара шатасуы (`н→ң`, `ұ→о`, `і→ү`), таза жазбада бұл дерлік
болмаған. Шу дыбысты жай "өшіріп тастамайды", оны міндетті түрде орысқа емес,
ұқсас қазақ фонемасына қарай ауытқытатын сияқты.

## 4. Сандарға қаншалықты сенуге болады

WER нұсқалары арасындағы алшақтықтың өзі бір нәтиже:

|  | FLEURS | Common Voice |
|---|---|---|
| WER_raw | 0.3725 | 0.6128 |
| WER_norm | 0.3055 | 0.5382 |
| WER_fold | 0.2924 | 0.5000 |
| WER_stem | 0.2833 | 0.4896 |
| CER_norm | 0.0617 | 0.1393 |
| delta_normalization | 0.067 | 0.0746 |
| delta_kk_graphemes | 0.0131 | 0.0382 |
| delta_morphology | 0.0222 | 0.0486 |

Екі дереккөзде де модель бірдей болғандықтан, `WER_norm` Common Voice-та
FLEURS-қа қарағанда 1.76 есе жоғары (0.54 мен 0.31), және бұл енді әлсіз
модель әсерімен араласпаған: бұл нақты шулы жазу жағдайының бағасы. `CER_norm`
одан да көп өсті, 2 еседен астам (0.14 мен 0.06), бұл логикалық: шулы жазбада
жеке дыбыстар зардап шегеді, тек толық сөздер емес.

95%-дық сенімділік аралығы (bootstrap, уттеранс бойынша 1000 қайта сынама алу):

FLEURS үшін `WER_norm ∈ [0.266, 0.348]`, 43 жазбада ауқымы 8 пункт. Common
Voice үшін `WER_norm ∈ [0.475, 0.605]`, 46 жазбада ауқымы 13 пункт. Осы
ауқымға қарамастан, екі аралық қиылыспайды: дереккөздер арасындағы айырма
нақты, үлгі шуы емес. Бірақ аралықтардың өзі 0.31 мен 0.54 санын дәл сан
ретінде емес, диапазон ретінде қабылдау керегін еске салады.

Метрика әділетсіз жазалайтын жер: WER "модель бір дауысты дыбыста қателесті"
дегенді және "модель кездейсоқ сөз айтты" дегенді ажыратпайды, екеуі де бірдей
ауыстыру болып саналады. Дәл сол себепті жобада төрт WER және бөлек типология
бар: "жақын форма" үлесі (3-бөлім) мағынаны түсінудегі нақты деградацияның
жалаң `WER_raw` айтқаннан әлдеқайда аз екенін көрсетеді.

## 5. Бір ай уақытым болса, алдымен нені түзетер едім

Реті маңызды, жай тізім емес:

1. Normalizer және морфологияны ескеретін метрика. Онсыз модельдің шынайы
   прогресі мен өлшеу шуын ажырату мүмкін емес: өз деректерімде
   `delta_morphology` екі дереккөздің арасында 2 еседен астам ерекшеленеді
   екенін көрдім, ал бұл айырмашылықты ескермейтін метрика domain gap-ты
   дөңгелектеу шуымен шатастырған болар еді.
2. Мақсатты деректер: code-switching және шын мәніндегі спонтанды сөйлеу,
   тағы бір оқылған корпус емес. Common Voice мұнда тек жарты шара (1-бөлімді
   қараңыз): жазу жағдайы басқа, бірақ мәтін бәрібір дайын мәтіннен оқылған.
   Бөлек міндет, табиғи қазақ тіліндегі сөйлеудің (қоңыраулар, сұхбат, подкаст)
   уттеранс деңгейінде транскрипцияланған жазбаларын табу немесе жинау.
   issai/Kazakh_Speech_Corpus_2 мазмұны бойынша дұрыс дереккөз сияқты көрінеді,
   бірақ audit үшін пайдаланар алдында бөлек сегментация жұмысын талап етеді.
3. Тек содан кейін fine-tuning, және алдымен бірнеше жүз мысалда `WER_stem`/`CER`
   қозғала ма деп тексеру керек, тек `WER_raw` емес.

## 6. Тығырыққа тірелген жерлер және не істелмеді

Осы прогонға техникалық ескертпелер (хронология емес, ол `LOG.md`-де):

Спонтанды қазақ тіліндегі сөйлеу үшін HF-те streaming-пен қолжетімді ешбір
датасет сай келмеді: issai/Kazakh_Speech_Corpus_2 теледидар/радио/подкаст
құрайды (спонтандыға ең жақыны), бірақ 80+ ГБ бір tar.gz түрінде, per-utterance
разметкасыз таратылады. Оны `refs.tsv` форматына бөлу бөлек, бір күнге сыймайтын
жұмыс.

Colab-та CUDA/nvrtc мәселесі болды: `datasets` аудионы `torchcodec` арқылы
декодтайды, ал ол `torch` арқылы нақты CUDA нұсқасын тартады. PyPI әдепкі
бойынша `libnvrtc.so.13` жетіспейтін сборканы таңдап қойды. `torch`/`torchcodec`-ті
`--index-url .../whl/cpu`-дан орнатумен түзетіледі (аудио декодтау CPU міндеті,
тану үшін GPU-ды `ctranslate2` береді, `torch` емес).

macOS-та FFmpeg мәселесі болды: сол `torchcodec` нақты FFmpeg нұсқаларына
(4-тен 8-ге дейін) линктелген, ал `brew install ffmpeg` 2026 жылы онымен
үйлеспейтін 9-нұсқаны орнатады. Шешімі мен командалары README-де, "Іске қосу"
бөлімінде.

Кейбір орталарда HF желісінде мәселе болды: FLEURS parquet-шардын жүктеу
кейде анық себепсіз timeout-пен құлайды (`datasets` ішіндегі retry жеткіліксіз
болатын кездер бар). Colab-та бұл қайталанбады, нақты желінің ерекшелігі
сияқты.

`LOG.md`-ді де қараңыз, онда жұмыс барысындағы өз әрекеттеріңіз бен
шешімдеріңізді жазыңыз, кейін артқа қарап қалпына келтірмей.

## ИИ қайда көмектесті

Claude Code (Anthropic) көмегімен жұмыс істедім, дерлік барлық кезеңде.
Нақты не істеді:

Кодтың негізгі бөлігін бірге жаздық: `prepare_data.py`-дегі екі дереккөзді
жүктеу логикасы, `evaluate.py`-дегі bootstrap confidence interval есебі,
`kk_text.py`-дегі нормализация мен стемминг эвристикасы түбірінен Claude-пен
бірге жазылды, мен тексеріп, өзгертулер сұрадым. `tests/` папкасындағы
unit test-терді де Claude жазды, мен оларды іске қостым, нәтижесінде екеуі
дереу жазылған кодтың мен күтпеген қылығын тапты.

Датасетті дайындауда Claude маған нақты көмектесті: FLEURS пен Common Voice-ты
HuggingFace-тен стриминг арқылы тарту кодын, сүзу логикасын (қысқа жазбаларды
алып тастау), екі инфрақұрылымдық ақаулықты (Colab-тағы CUDA/nvrtc, өз
компьютеріндегі FFmpeg нұсқасы) тапты және түзетті. Прогондардың өзін мен
іске қостым: Colab-та FLEURS пен Common Voice-ты `large-v3` моделімен,
локальді компьютерде қосымша тексеру ретінде.

Осы README-дегі есеп мәтінін, LOG.md жазбаларын және форма үшін жауап
мәтінін Claude-пен бірге құрастырдым: нақты сандар мен фактілер нақты
прогондардан алынды, ал мәтіннің құрылымы мен тұжырымдар Claude-пен
бірлескен жұмыстың нәтижесі. Мен әр сан мен тұжырымды өзім тексердім,
бірақ мәтіннің көп бөлігін бастапқыда Claude жазды.
